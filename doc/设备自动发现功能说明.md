# 设备自动发现功能说明

## 功能概述

MQTT Monitor 现在支持通过心跳机制自动发现和管理IoT设备。设备通过定期发送心跳消息到指定的Topic，系统会自动识别设备、订阅设备的数据Topic，并监控设备的在线状态。

## 主要特性

1. **自动设备发现**：设备发送心跳消息后自动注册到系统
2. **自动订阅管理**：系统自动订阅/取消订阅设备的数据Topic
3. **在线状态监控**：实时监控设备在线状态，超时自动标记为离线
4. **设备列表管理**：提供友好的设备列表界面，显示设备信息和状态
5. **订阅类型隔离**：自动订阅和手动订阅完全分离，互不干扰

## 配置说明

### config.json 配置项

在 `config.json` 中添加以下配置：

```json
{
  "BaseTopic": "iot/devices",
  "HeartbeatTopic": "iot/devices/heartbeat",
  "HeartbeatTimeoutSeconds": 60,
  "EnableDeviceDiscovery": true
}
```

**参数说明：**

- `BaseTopic`: MQTT基础Topic（用于命令发送和构建心跳Topic）
- `HeartbeatTopic`: 设备心跳Topic，设备需要向此Topic发送心跳消息
  - **智能构建**：如果 `HeartbeatTopic` 为空或为默认值，系统会自动基于 `BaseTopic` 构建
  - 例如：`BaseTopic = "iot/devices"` → `HeartbeatTopic = "iot/devices/heartbeat"`
  - 例如：`BaseTopic = "factory/sensors"` → `HeartbeatTopic = "factory/sensors/heartbeat"`
  - 如果需要自定义心跳Topic，可以在配置文件中明确指定
- `HeartbeatTimeoutSeconds`: 心跳超时时间（秒），超过此时间未收到心跳则设备标记为离线
- `EnableDeviceDiscovery`: 是否启用设备自动发现功能

**⚠️ 重要说明**：
- 当 `BaseTopic` 改变时，`HeartbeatTopic` 会自动跟随变化（如果使用默认值）
- 后缀 `/heartbeat` 是固定的
- 设备发送心跳时必须使用与系统相同的心跳Topic

## 心跳消息格式

设备需要定期向配置的心跳Topic发送JSON格式的心跳消息：

### 必需字段

```json
{
  "deviceId": "ENV-001",
  "dataTopic": "iot/devices/ENV-001/datas"
}
```

### 完整格式（包含可选字段）

```json
{
  "deviceId": "ENV-001",
  "dataTopic": "iot/devices/ENV-001/datas",
  "deviceName": "环境监测设备-001",
  "deviceType": "环境监测",
  "timestamp": 1730489461521
}
```

**字段说明：**

- `deviceId` (必需): 设备唯一标识符
- `dataTopic` (必需): 设备数据发布的Topic
- `deviceName` (可选): 设备名称，用于显示
- `deviceType` (可选): 设备类型，用于分类
- `timestamp` (可选): 心跳时间戳（Unix毫秒级）

## 使用指南

### 1. 启用功能

1. 编辑 `config.json`，设置 `EnableDeviceDiscovery: true`
2. 配置 `HeartbeatTopic` 和 `HeartbeatTimeoutSeconds`
3. 启动程序并连接MQTT服务器

连接成功后，设备管理服务会自动启用并开始监听心跳消息。

### 2. 查看设备列表

点击菜单栏 **设备(D)** -> **设备管理(M)**，打开设备管理窗口。

**设备列表显示内容：**
- 设备ID
- 设备名称
- 设备类型
- 数据Topic
- 最后心跳时间
- 在线状态（在线/离线）

**统计信息：**
- 在线设备数量 / 总设备数量
- 心跳超时时间
- 服务运行状态

### 3. 设备心跳发送示例

#### Python示例

```python
import paho.mqtt.client as mqtt
import json
import time

# MQTT配置
BROKER = "119.45.181.86"
PORT = 1883
USERNAME = "admin"
PASSWORD = "your_strong_password"
HEARTBEAT_TOPIC = "iot/devices/heartbeat"

# 设备信息
DEVICE_ID = "ENV-001"
DATA_TOPIC = "iot/devices/ENV-001/datas"

client = mqtt.Client()
client.username_pw_set(USERNAME, PASSWORD)
client.connect(BROKER, PORT, 60)

while True:
    # 构建心跳消息
    heartbeat = {
        "deviceId": DEVICE_ID,
        "dataTopic": DATA_TOPIC,
        "deviceName": "环境监测设备-001",
        "deviceType": "环境监测",
        "timestamp": int(time.time() * 1000)
    }

    # 发送心跳
    client.publish(HEARTBEAT_TOPIC, json.dumps(heartbeat))
    print(f"心跳已发送: {DEVICE_ID}")

    # 每30秒发送一次心跳
    time.sleep(30)
```

#### Arduino/ESP32示例

```cpp
#include <WiFi.h>
#include <PubSubClient.h>
#include <ArduinoJson.h>

const char* ssid = "your-wifi-ssid";
const char* password = "your-wifi-password";
const char* mqtt_server = "119.45.181.86";
const char* mqtt_user = "admin";
const char* mqtt_password = "your_strong_password";
const char* heartbeat_topic = "iot/devices/heartbeat";

const char* device_id = "ESP32-001";
const char* data_topic = "iot/devices/ESP32-001/datas";

WiFiClient espClient;
PubSubClient client(espClient);

void sendHeartbeat() {
    StaticJsonDocument<256> doc;
    doc["deviceId"] = device_id;
    doc["dataTopic"] = data_topic;
    doc["deviceName"] = "ESP32设备-001";
    doc["deviceType"] = "温湿度传感器";
    doc["timestamp"] = millis();

    char buffer[256];
    serializeJson(doc, buffer);
    client.publish(heartbeat_topic, buffer);
    Serial.println("Heartbeat sent");
}

void loop() {
    client.loop();

    // 每30秒发送一次心跳
    static unsigned long lastHeartbeat = 0;
    if (millis() - lastHeartbeat > 30000) {
        sendHeartbeat();
        lastHeartbeat = millis();
    }
}
```

## 工作原理

### 1. 设备注册流程

```
设备 -> 发送心跳消息 -> MQTT Broker -> MQTT Monitor
                                              |
                                              v
                                       解析心跳消息
                                              |
                                              v
                                    设备已存在？
                                    /           \
                                  是             否
                                  |              |
                            更新心跳时间      创建新设备
                            更新设备信息      自动订阅数据Topic
                                              添加到设备列表
```

### 2. 在线状态监控

系统每10秒检查一次所有设备的心跳时间：

```
当前时间 - 最后心跳时间 < 超时时间 (60秒) -> 在线
当前时间 - 最后心跳时间 >= 超时时间 (60秒) -> 离线
```

### 3. 自动订阅管理

- **新设备接入**：自动订阅设备的 `dataTopic`
- **设备Topic变更**：自动取消订阅旧Topic，订阅新Topic
- **断开连接**：自动取消订阅所有设备Topic
- **重新连接**：自动重新订阅所有设备Topic

### 4. 订阅类型隔离

系统内部维护两个独立的订阅列表：

- **手动订阅列表**：通过右侧"Topic订阅管理"面板手动添加的订阅
- **自动订阅列表**：通过设备心跳自动添加的订阅

两者互不影响：
- 手动订阅列表只显示用户手动添加的Topic
- 自动订阅的设备Topic不会出现在手动订阅列表中
- 日志中会标记 `[自动]` 或 `[手动]` 以区分订阅类型

## 注意事项

1. **心跳间隔建议**：
   - 建议心跳间隔为超时时间的 1/3 到 1/2
   - 例如超时时间60秒，建议每20-30秒发送一次心跳

2. **设备ID要求**：
   - 设备ID必须唯一
   - 建议使用设备MAC地址或UUID作为设备ID

3. **Topic规范**：
   - 建议遵循统一的Topic命名规范
   - 例如：`iot/devices/{deviceId}/datas`

4. **性能考虑**：
   - 大量设备接入时，建议适当增加心跳超时时间
   - 减少心跳发送频率以降低网络开销

5. **网络稳定性**：
   - 心跳机制可以有效检测网络断连
   - 建议在设备端实现MQTT自动重连机制

## 故障排查

### 设备未出现在设备列表中

1. 检查设备是否成功连接到MQTT Broker
2. 检查心跳Topic配置是否正确
3. 检查心跳消息格式是否符合要求（必须包含 `deviceId` 和 `dataTopic`）
4. 查看日志标签页，确认是否收到心跳消息

### 设备显示为离线

1. 检查设备是否正常发送心跳
2. 检查心跳发送间隔是否小于超时时间
3. 检查网络连接是否稳定
4. 查看设备的"最后心跳时间"，确认最后一次心跳时间

### 未自动订阅设备Topic

1. 检查日志是否有订阅错误
2. 检查设备心跳消息中的 `dataTopic` 字段是否正确
3. 确认MQTT连接状态正常

## 示例场景

### 场景1：环境监测系统

有10个环境监测设备分布在不同位置，每个设备监测温度、湿度、PM2.5等数据。

**配置：**
```json
{
  "HeartbeatTopic": "iot/env/heartbeat",
  "HeartbeatTimeoutSeconds": 120
}
```

**设备心跳：**
- 每60秒发送一次心跳
- 包含设备位置信息（deviceName）
- 包含设备类型（deviceType: "环境监测"）

**优势：**
- 新增设备自动接入，无需手动配置
- 设备离线自动检测，及时发现故障
- 统一管理所有环境监测设备

### 场景2：智能家居系统

家中有多种智能设备（灯、空调、传感器等）

**配置：**
```json
{
  "HeartbeatTopic": "smarthome/heartbeat",
  "HeartbeatTimeoutSeconds": 60
}
```

**设备分类：**
- deviceType: "照明" - 智能灯
- deviceType: "空调" - 空调设备
- deviceType: "传感器" - 各类传感器

**优势：**
- 按类型分类显示设备
- 快速识别离线设备
- 设备即插即用
